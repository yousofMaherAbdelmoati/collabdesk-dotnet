# NET-003 evidence report

## Changes

- Added validated ticket and status request DTOs, typed OpenAPI response metadata, and RFC7807 problem responses for ticket validation, conflicts, ownership, and missing resources.
- Added role-filtered, paginated ticket listing; only customers see their tickets, agents see open work plus work assigned to them, and administrators see all tickets.
- Added conditional database-backed status transitions: open tickets can be claimed once and only the assigned agent can transition a claimed ticket to resolved.
- Added participant-authorized, paginated HTTP message history and strengthened SignalR message de-duplication so a client message identifier cannot be replayed by another sender or with altered content.
- Reworked idempotent creation so the idempotency row, ticket, stored response, and outbox event commit in one transaction. Database unique-violation recovery returns the stored response, rejects fingerprint mismatches, and only removes an expired legacy processing record through a conditional database delete.
- Added `20261024102541_AddTicketContractIndexes` for request-size constraints and ticket/message query indexes.
- Added API contract tests and PostgreSQL acceptance tests using separate `DbContext` instances/connections. The test database is required to be named `collabdesk_test_*` before it will be dropped and recreated.

## Security notes

- Correctness uses PostgreSQL transactions, a unique idempotency index, and conditional `UPDATE` statements; no process-local lock is used.
- Existing cookie authentication, CSRF metadata, CORS, and participant authorization remain in place.
- Error responses now use RFC7807-compatible problem details without exposing exception messages.
- The PostgreSQL test fixture refuses any database name not prefixed `collabdesk_test_` before destructive test setup.
