# NET-001 evidence report

## Changes

No application-source repair was required: the repository already contains all five projects in `CollabDesk.sln`, targets `net10.0`, pins EF Core 10.0.13 with the compatible Npgsql EF Core 10.0.3 provider, treats warnings as errors, and has a checked-in PostgreSQL initial migration.

The existing development initializer applies checked-in migrations and fictional `*.test` seeds only for the `Development` environment. Its unit tests verify that it is disabled for Staging and Production. The Compose file exposes only API host port `5000`; PostgreSQL and Redis are attached solely to the internal `backend` network. This report is the only file added by NET-001.

## Host prerequisites found

- .NET SDK `10.0.113` (runtime `10.0.13`)
- Docker `29.9.2` and Docker Compose `v5.6.1`
- `psql` and `redis-cli` are not installed on the host. This did not block verification because the official PostgreSQL and Redis Compose containers provide both clients.

## Remaining gaps

- The included concurrency specification remains intentionally skipped because it needs a dedicated disposable PostgreSQL test fixture. It is outside NET-001's build, migration, Compose, and health acceptance checks; live PostgreSQL migration and health were verified above.
- Host-side PostgreSQL/Redis CLIs remain optional prerequisites. For host-only diagnostics, install `postgresql-client` and `redis-tools`; they are not needed for the documented Compose commands.

## Security notes

- The Compose credentials and seeded users are fictional, local-development-only values. Do not reuse them outside local development.
- Production startup does not auto-migrate or seed. Apply reviewed, checked-in migrations explicitly with `dotnet ef database update` and deployment-managed secrets.
- PostgreSQL and Redis are not published to the host and are isolated on the Compose internal backend network; only the API is exposed at port 5000, leaving port 3000 available for a frontend.
