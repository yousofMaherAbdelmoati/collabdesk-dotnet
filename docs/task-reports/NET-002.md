# NET-002 evidence report

## Changes

- Replaced the placeholder authentication arrangement with ASP.NET Core cookie authentication and `PasswordHasher<AppUser>`.
- Added `AuthSession` persistence, a 30-minute non-sliding cookie/session expiry, and server-side validation on every authenticated request. Logout revokes the database session before clearing the cookie.
- Added login, logout, and CSRF-token endpoints. All state-changing API routes require an antiforgery header; cookies are `HttpOnly`, `Secure`, `SameSite=Strict`, and host-prefixed.
- Added `AgentOnly` and ticket-participant authorization policies. Ticket participant checks protect the assistant stream and both SignalR hub methods; the hub is mapped with required authentication and the CORS policy.
- Added exact-origin credentialed CORS policy configuration. Development permits only `https://localhost:3000`; absent deployment configuration permits no browser origin.
- Added `NormalizedEmail`, a unique normalized-email index, and `AuthSessions` via migration `20261024100451_AddSecureAuthSessions`.
- Updated Development-only fictional fixture accounts to use valid Identity password hashes, including a safe upgrade path for the former non-hash placeholder values.
- Added in-process API integration tests using a disposable SQLite database for password hashing, login/logout/revocation, expiry enforcement, anonymous restriction, role misuse, horizontal access, SignalR negotiation authentication, and SignalR CORS behavior.

## Remaining gaps

- The API integration tests use SQLite in-process to avoid shared services; PostgreSQL was additionally validated for migration/startup only. No browser or load testing was run.
- The pre-existing ticket-claim concurrency specification remains skipped because it requires a dedicated disposable PostgreSQL concurrency fixture. It is not an authentication acceptance test.
- The local Compose endpoint is HTTP-only, while auth cookies deliberately require HTTPS. End-to-end browser login therefore requires TLS termination in a deployment or local HTTPS setup.

## Security notes

- Passwords are never stored or logged in cleartext. Fixture accounts are Development-only and use fictional `*.test` addresses.
- Every authenticated cookie is cryptographically protected by ASP.NET Core Data Protection, expires after 30 minutes, is non-sliding, and is checked against a revocable server-side session record.
- API authentication failures return 401 and authorization failures return 403 rather than cookie-login redirects.
- Client-supplied user identifiers are not accepted for ticket ownership or hub sender identity; identities come exclusively from authenticated claims.
- CORS uses configured exact origins with credentials, and unsafe browser requests require the antiforgery token issued by the API.
