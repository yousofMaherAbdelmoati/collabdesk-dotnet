# NET-005 evidence report

## Changes

- Replaced the inline delayed assistant response loop with `IAssistantStreamProvider` and a DI-registered, deterministic local provider. It requires no model key or network service.
- Added `AssistantStreamService`, which writes flushed SSE `token`, `complete`, and terminal `error` frames; retains sequence order; propagates request cancellation; and applies independent timeout, token-count, and output-character limits.
- Added validated `AssistantStreamOptions` defaults: 32 tokens, 4,096 output characters, and 15 seconds.
- Added structured logs with event IDs and ticket, trace, chunk, character, and provider fields for completion, timeout, disconnect, limit, and provider-failure paths.
- Added four automated stream specifications: two authenticated concurrent HTTP streams with ordered frames, provider failure framing, cancellation release, and timeout/output-bound errors.

## Commands executed

```bash
dotnet build CollabDesk.sln --no-restore --warnaserror
dotnet test tests/CollabDesk.IntegrationTests/CollabDesk.IntegrationTests.csproj --no-build --no-restore --filter "FullyQualifiedName~AssistantStreamSpecification" --logger "console;verbosity=minimal"
dotnet test CollabDesk.sln --no-build --no-restore --logger "console;verbosity=minimal"
```

## Results

- Build succeeded with 0 warnings and 0 errors.
- Focused stream tests: 4 passed, 0 failed, 0 skipped.
- Full suite: 25 passed, 0 failed, 3 skipped. The skips are pre-existing PostgreSQL concurrency tests and explicitly require `COLLABDESK_TEST_POSTGRES`; they are outside NET-005's stream coverage.
- The stream tests use ASP.NET Core's in-process test server and fictional SQLite-backed identities/tickets. They verify two simultaneous authenticated route requests, monotonically ordered token sequences, terminal completion, provider error framing, timeout/output bounds, and simulated client-request cancellation reaching and releasing the provider.

## Remaining gaps

- PostgreSQL, Redis, Docker, browser, real Kestrel socket-disconnect, and load testing were not run or claimed. They are not prerequisites for the deterministic local assistant provider or its in-process automated coverage.
- No paid LLM provider was configured or contacted.

## Security notes

- The provider is local and deterministic; no key, secret, customer data, or external model call is used.
- SSE provider exceptions are logged server-side with structured diagnostics but exposed to clients only as a generic `provider_failure` message.
- Existing authorization and ticket-participant checks remain before streaming starts. Response buffering is disabled, cache is disabled, and output/time limits bound resource use.
