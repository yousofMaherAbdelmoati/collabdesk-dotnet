# NET-012 — .NET reports and cache benchmark

## Result

PASS. The benchmark ran against disposable local PostgreSQL and Redis services for every supported
fixture size (10,000, 50,000, and 100,000 tickets). Every measured strategy returned the same
90-day daily ticket-report rows before its latency was recorded.

## Changes

- Added `ReportBenchmarkFixture`, which creates deterministic, fictional ticket/user fixtures for
  exactly 10k, 50k, and 100k tickets (default seed `12012`) and rejects any database name outside
  the `collabdesk_benchmark_` namespace.
- Added `tools/CollabDesk.Benchmarks`, an executable with `seed` and `run` commands. It applies
  checked-in migrations, truncates only the guarded benchmark database, prepares durable daily
  aggregates, seeds Redis, validates result equivalence, and saves individual warmup/measurement
  observations as JSON.
- Added fixture determinism and destructive-target guard tests.
- Documented reproducible commands in `README.md`.

## Environment and workload

- Host: Ubuntu 24.04.5 LTS; .NET runtime 10.0.13.
- Disposable services: PostgreSQL 16.15 and Redis 7.4.11, started under Compose project
  `collabdesk-net012`; PostgreSQL database `collabdesk_benchmark_net012`.
- Fixed UTC report window: 2026-01-01 through 2026-03-31 (90 days).
- Each size: 3 warmups plus 15 recorded measurements per strategy. Latencies below are recorded
  measurement averages (min–max), in milliseconds. The raw files contain every observation,
  including warmups and the materialization setup duration.

| Tickets | Precompute setup | On-demand EF (queries) | Precomputed (queries) | Redis cached (queries) |
| ---: | ---: | ---: | ---: | ---: |
| 10,000 | 2528.924 ms | 11.021 (10.593–15.132), 3 | 0.978 (0.942–1.034), 1 | 0.521 (0.429–0.609), 0 |
| 50,000 | 11434.439 ms | 38.508 (36.336–40.716), 3 | 0.859 (0.702–2.069), 1 | 0.514 (0.404–0.702), 0 |
| 100,000 | 25232.862 ms | 78.819 (75.830–82.578), 3 | 0.744 (0.555–2.281), 1 | 0.562 (0.400–0.667), 0 |

The comparison intentionally measures a warm local service/cache path, not a production load test.
`on-demand-ef` executes three EF Core grouped SQL aggregations (created; claimed plus response
time; resolved). `precomputed` reads `DailyTicketStats`; `redis-cached` reads the serialized,
equivalence-checked precomputed result. No percentage improvement is asserted because these are
single-host measurements rather than a controlled capacity study.

## Commands executed

```bash
dotnet restore CollabDesk.sln
dotnet build CollabDesk.sln --no-restore --warnaserror
dotnet test CollabDesk.sln --no-build --no-restore --filter 'FullyQualifiedName~BenchmarkFixtureSpecification'
POSTGRES_DB=collabdesk_benchmark_net012 docker compose -p collabdesk-net012 -f docker-compose.yml -f docker-compose.test.yml up -d --wait db redis
COLLABDESK_BENCHMARK_POSTGRES='Host=127.0.0.1;Port=55433;Database=collabdesk_benchmark_net012;Username=collabdesk;Password=collabdesk' dotnet run --project tools/CollabDesk.Benchmarks --no-build -- seed --size 10000
COLLABDESK_BENCHMARK_POSTGRES='Host=127.0.0.1;Port=55433;Database=collabdesk_benchmark_net012;Username=collabdesk;Password=collabdesk' COLLABDESK_BENCHMARK_REDIS='127.0.0.1:56380' dotnet run --project tools/CollabDesk.Benchmarks --no-build -- run --size 10000 --warmup 3 --iterations 15 --results docs/benchmarks/net-012-10000.json
# Repeated the preceding seed/run pair for 50000 and 100000, writing matching result files.
dotnet test CollabDesk.sln --no-build --no-restore
```

An additional loopback guard check with a documentation-only non-routable host
(`203.0.113.1`) failed before attempting a connection, as designed.

Results: build passed with zero warnings; focused benchmark-fixture tests passed (11); full suite
passed (57), with 3 existing Redis/Compose tests skipped because their opt-in test environment
variables were not supplied to that test invocation. The separate benchmark commands above did
connect to and validate the disposable PostgreSQL/Redis services.

## Remaining gaps

- This is intentionally not a concurrency/load, cold-cache, or production-hardware benchmark.
- The benchmark requires a local PostgreSQL database named with the documented benchmark prefix
  and a local Redis endpoint. It fails closed if either is absent or the ticket count is not exact.

## Security notes

- All users, ticket titles/descriptions, email addresses, dates, and IDs are deterministic
  fictional local fixtures; no customer or production data was read or written.
- The runner requires `collabdesk_benchmark_` and a loopback PostgreSQL host before it migrates or
  truncates a database; it also accepts only loopback Redis endpoints. It never emits the
  PostgreSQL connection string or Redis endpoint into raw measurement files.
- The Compose services were loopback-only through the existing test override and are cleaned up
  under their exact `collabdesk-net012` project name.
