# NET-011 evidence report

## Changes

- Replaced the prior Playwright smoke scenario with a real-browser NET-011 test in `frontend/e2e/demo.spec.ts`.
  - It opens isolated customer, agent, and administrator contexts using only the local fictional `*.test` fixtures.
  - It creates and claims a ticket, verifies a live SignalR message and a customer read receipt, closes the customer's page, sends a message while disconnected, and verifies the fresh customer page receives the persisted history.
  - It makes a same-origin, CSRF-protected customer request to the agent-only claim endpoint and asserts the real HTTP `403` response.
  - It starts and cancels a real `/api/assistant/stream` response and asserts Chromium reports the request as `ERR_ABORTED`.
  - It requests a report as the administrator and waits for the running worker to produce its completed result.
- Added a bounded `AssistantStream:InterTokenDelayMilliseconds` option. It is `0` by default and set to 100 ms only in Development, allowing the deterministic local stream to be visibly paced and cancellable without changing non-development latency.
- Captured real running-app screenshots during the successful Playwright run:
  - `frontend/test-results/demo-NET-011-real-browser--501c6-SE-cancellation-and-reports/net-011-customer-live-chat.png`
  - `frontend/test-results/demo-NET-011-real-browser--501c6-SE-cancellation-and-reports/net-011-customer-reconnected-history.png`
  - `frontend/test-results/demo-NET-011-real-browser--501c6-SE-cancellation-and-reports/net-011-admin-report-completed.png`

## Remaining gaps

- The standard .NET suite's three external-service tests remain skipped unless the isolated `COLLABDESK_TEST_POSTGRES` and `COLLABDESK_TEST_REDIS` endpoints are supplied. They were not needed for the browser workflow because that workflow used the live local Compose services.

## Security notes

- Only fictional local `*.test` fixture accounts and the documented local fixture password were used. No production service, real customer data, secret, deployment, commit, push, or publication was accessed or performed.
- The forbidden check used the browser's same-origin session and CSRF token; authorization remained enforced by the server's `AgentOnly` policy rather than hidden solely in the UI.
- The Development-only token pacing is bounded to 0–5000 ms and defaults to no delay outside Development. It exists solely to exercise abort propagation against the deterministic local provider.
