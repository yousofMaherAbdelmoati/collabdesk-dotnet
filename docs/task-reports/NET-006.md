# NET-006 evidence report

## Changes

- Added `TicketReadCache`, a best-effort `IDistributedCache` cache-aside layer registered over the existing StackExchange Redis provider.
- Added versioned, namespaced keys under `collabdesk:v1` for customer/agent ticket lists, ticket message pages/history, agent stats, and their invalidation tokens. Payloads have a two-minute TTL; version tokens expire after 24 hours.
- Cached ticket lists are scoped by authenticated user and role; message reads retain the existing database-backed participant authorization before cache access. Agent stats are scoped to the authenticated agent.
- Ticket creation, claim, and resolve advance the affected list/stat versions. Persisting a new SignalR chat message advances that ticket's message version only after the database save succeeds.
- Added OpenTelemetry-compatible `System.Diagnostics.Metrics` counters for cache hits, misses, and failures, plus warning logs that do not expose keys or payloads.
- Added per-key asynchronous miss coalescing to prevent same-process concurrent cache misses from repeatedly loading the database. Cache get/set/version failures return the authoritative database result.
- Added `/api/agents/stats` for authenticated agents and local automated coverage for ticket cache reads, invalidation, identity isolation, agent-stat invalidation, message invalidation, concurrent misses, Redis outage fallback, and a real Redis-backed second-read hit.

## Results

- Both builds succeeded with 0 warnings and 0 errors.
- Focused cache specifications: 5 passed, 0 failed, 0 skipped.
- Disposable Docker Redis 7 returned `PONG`; the real Redis cache acceptance test passed (1 passed, 0 failed).
- Full suite: 30 passed, 0 failed, 4 skipped. The Redis acceptance test is intentionally skipped unless `COLLABDESK_TEST_REDIS` points to a local Redis instance. Three pre-existing PostgreSQL concurrency checks remain skipped because `COLLABDESK_TEST_POSTGRES` was not configured.
- The disposable Redis container was stopped and removed after validation.

## Remaining gaps

- PostgreSQL-specific concurrency specifications were not run because no isolated `COLLABDESK_TEST_POSTGRES` database was supplied. They are unrelated pre-existing tests; cache behavior was tested with fictional SQLite data and a disposable local Redis instance.
- No browser, deployment, production service, or load test was run.
- Miss coalescing is process-local. Redis remains an optional cache and database truth is preserved if it is unavailable; cross-process distributed locking is not configured.

## Security notes

- Cache values are scoped by authenticated user/role where ticket visibility differs. Ticket message cache access occurs only after the existing database authorization check, so cached history cannot grant access.
- Cache keys use opaque numeric identifiers and normalized GUIDs; no titles, message bodies, credentials, or customer data are embedded in keys or logs.
- Redis errors are logged generically and degrade to database reads; Redis is not used for authorization, mutation correctness, or durable state.
