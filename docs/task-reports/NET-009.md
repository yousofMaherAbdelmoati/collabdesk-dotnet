# NET-009 — .NET integration and stress tests

## Result

PASS. The real-service acceptance path completed locally against disposable Docker Compose
PostgreSQL 16 and Redis 7: **48 passed, 0 failed, 0 skipped**.

## Changes

- Added `docker-compose.test.yml`, a test-only override that exposes PostgreSQL and Redis on
  loopback ports `55433` and `56380` and attaches them to a separate test network. Normal Compose
  remains unchanged: its data services have no host ports.
- Added a CI `integration` job that starts those disposable services, supplies only local test
  connection strings, builds the whole solution, runs the whole test suite, and always removes
  containers and volumes.
- Added Compose-backed API tests covering migration application, cookie authentication,
  customer-to-agent role escalation denial, agent claim success, Redis-backed cache invalidation,
  20 concurrent idempotent ticket creates, and 20 concurrent report submissions.
- Added authenticated SignalR long-polling transport coverage through the actual negotiate/connect
  pipeline. It verifies a participant message is delivered and persisted in PostgreSQL.
- Added a 20-way PostgreSQL chat retry test proving the `(TicketId, ClientMessageId)` uniqueness
  contract persists one message only.
- Retained the existing real PostgreSQL lease/restart/outbox tests and Redis-outage/cache fallback
  tests; CI now supplies their dependencies so they are not skipped.
- Documented the local real-service test command in `README.md`.

No acceptance-criterion gaps remain. The Compose tests intentionally skip only when their two
explicit local endpoints are absent; CI provides both endpoints and the verified real-service run
had zero skips.

## Security notes

- All records, users, passwords, tickets, chat text, and reports are fictional local fixtures.
- The test reset refuses any database not named `collabdesk_test_*` before destructive operations.
- Test dependency ports are loopback-only and are removed with the disposable Compose project.
- No production services, customer data, secrets, deployment, publishing, commits, or pushes were
  used.
