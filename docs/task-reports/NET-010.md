# NET-010 evidence report

## Delivered changes

- Replaced the placeholder with a React/TypeScript Vite client under `frontend/`.
  - Customer: creates retry-safe demo tickets, joins ticket chat, receives/sends SignalR messages, advances durable read state, and starts/cancels assistant SSE.
  - Agent: refreshes work, claims/resolves its assigned tickets, and joins the same ticket chat.
  - Administrator: creates/cancels asynchronous report jobs, polls their durable state, and caches completed result data in the current browser.
  - SignalR uses automatic reconnect and resynchronizes persisted history after reconnect.
  - The browser creates ticket idempotency keys in `sessionStorage` and uses in-memory in-flight guards only as local UI controls; server-side idempotency and conditional updates remain authoritative.
- Added `GET /api/auth/me`, which returns the authenticated server-issued identity/role rather than trusting client-provided role data.
- Added a Development-only fictional administrator fixture (`demo-admin@collabdesk.test`), alongside the existing customer and agent fixtures. All fixtures use the documented local password.
- Docker now builds the React bundle in a Node stage and ASP.NET Core serves it from the same `http://localhost:5000` origin. Port 5000 remains intentionally separate from typical Django 3000/8000 development ports. `frontend/node_modules` and `frontend/dist` are excluded from Docker build context.
- In Development only, local HTTP uses non-`__Host-` cookie names and `SameAsRequest`; browsers reject insecure `__Host-` cookies. Non-Development retains secure `__Host-` cookies and `Always` secure policy.
- Added the authenticated identity contract test and a Playwright smoke/E2E test using three isolated browser contexts.

## Remaining gaps

- This is a local demonstration, not a production UI. It has not been load tested or deployed.
- The normal local Compose stack remains running on port 5000 after browser verification; it was not torn down because its volume predated this task.
- The existing single-instance SignalR limitation remains documented in `README.md`; no Redis SignalR backplane was added.

## Security notes

- No real users, external services, production credentials, or secrets were accessed.
- Development seed users and the local fixture password are explicitly local-only. Production authentication, HTTPS, CORS, CSRF policy, secrets, and rate limits still require deployment-specific review.
- The UI does not expose privileged actions based on client role input. Admin report endpoints remain protected by the server-side administrator authorization policy.
- Browser result caching and UI concurrency guards are convenience controls only; durable idempotency, report leases, authorization, and ticket transitions remain enforced by the API/database.
