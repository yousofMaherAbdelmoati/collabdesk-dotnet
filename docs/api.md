# API guide

Start the local stack and retrieve the generated, typed contract at [`/openapi/v1.json`](http://localhost:5000/openapi/v1.json). The document is generated by `Microsoft.AspNetCore.OpenApi`; it is the authoritative request/response schema. The table below is a reviewer-oriented map, not a replacement for that contract.

| Area | Endpoints | Access / notes |
| --- | --- | --- |
| Health | `GET /health` | EF Core database health check. |
| Session | `GET /api/auth/csrf`, `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout` | Login creates a server-side session and HTTP-only cookie. State-changing endpoints require `X-CSRF-TOKEN`. |
| Tickets | `POST, GET /api/tickets`; `POST /api/tickets/{id}/claim`; `POST /api/tickets/{id}/status` | Authenticated users create/list; agents claim/resolve. Creation requires an `Idempotency-Key`. |
| Ticket messages | `GET /api/tickets/{id}/messages` | Ticket participants only; paginated history. |
| Agent stats | `GET /api/agents/stats` | Agent-only. |
| Reports | `POST /api/reports`; `GET /api/reports/{id}`, `/result`, `/download/{format?}`; `DELETE /api/reports/{id}` | Administrator-only durable report workflow; `format` is `json` or `csv`. |
| Assistant | `POST /api/assistant/stream` | Ticket participant only; accepts only `ticketId`; streams a bounded deterministic local demo response, not user prompts or AI output. |
| Live chat | SignalR `/ws/tickets` | Authenticated connection plus per-ticket authorization. |

Failures use RFC 7807-style `application/problem+json` responses. Ticket input, page sizes, report dates, and state transitions are validated at the API boundary. The contract has integration coverage in `Ticket_contract_is_described_in_the_typed_openapi_document`.

Local browser usage is same-origin through Compose. Development relaxes the cookie transport only for the local HTTP demo. A real deployment needs HTTPS, reviewed CORS origins, production secrets, authentication policy, rate limits, and observability.
